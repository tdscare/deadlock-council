## 5.6 VERIFIED OPERATING ENVELOPE (written into ctl\bg_limits.json after CT-1; values below are the proposal)
- Launch: only via launcher_hidden.vbs -> supervisor_v2 -> sandbox_run_v5_hidden (CreateNoWindow, UseShellExecute=false, cmd redirect). Anything else is out of envelope.
- Priority: server BelowNormal (or Normal if CT-1 shows no difference and BelowNormal hurts tick), supervisor BelowNormal, telemetry/probe Idle, builds Idle.

## 5.7 Autonomous recovery policy
Recoverable without asking (log + continue): task timeout/abort, soft reset, session lost and returns (gate), server crash (restart hidden via supervisor, max 3/hour, queue resumes from snapshot, orphan task refunded), display kill switch trip (continue with display off), plugin command failure/retry per rules, timing-invalid window (task re-queued with notBefore backoff), load spike (ADAPT: defer builds, lower priority one step, wait/backoff, retry later), data/plan changes (no rebuild), disk log rotation, hot reload of an already VERIFIED build (hash in registry) while idle+PAUSEd by maintenance protocol only if the envelope permits it.
Must stop and ask: deploying a NEW plugin build (new source hash), changing the execution environment (launch method, priorities outside envelope, affinity outside envelope, client settings, autoexec), restarting components in a way not yet verified nonintrusive (e.g. client launch, anything needing a window), any recovery needing desktop focus/mouse/keyboard, repeated crashes (>3/hour), repeated timing invalidation (>=3 tasks in a row), a window/focus change observed, disk > 90%, queue corruption, session gate failures that persist >30 min (report, keep PAUSE).
Adapt-not-stop ladder: (1) defer expensive maintenance, (2) lower priority one step / reduce concurrency (already 1), (3) delay next task, (4) pause only affected task with state preserved and report.
