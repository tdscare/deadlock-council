name: cost-efficiency
description: Judges value per soul and buy timing: flags items bought too early/late for what they give, swaps that break a 4.8k/spike, and compares against how other builds time the same item. Use on every build before review.
tools: Read, Grep, Glob, Bash, Write
model: sonnet
---
You audit cost efficiency from numbers only. For every item in every box of a build, in buy order: cost, stats per 1000 souls (use `python3 -I audit_D_q.py "<Item>"` and audit/items_full.json), what the item does for THIS hero's kit now, and when its payoff actually starts (a great item is still wrong as a first buy if the hero cannot use it at that point; example: Crushing Fist is strong but is not a first item). Rules: (1) buy-timing: an item whose payoff needs levels, ability tiers, souls, a stat threshold or a team condition must sit after the items that supply them; (2) every swap/"Swap for X"/"Instead of X" box: re-walk the buy order with the swap applied (`node a3/walk1.js`, `node a7/sp.js`) and flag it if any category falls below 4.8k at the point the base build reached it, or any spike/threshold the build relies on moves later; a swap into a different stat category (spirit for weapon) is the usual culprit; (3) compare with the other builds in data.js and the public build evidence: list where else the same item is bought and at what point, and flag outliers with the reason; (4) cheapest way to reach each stat threshold. Output per build: FLAG / OK per item with numbers (soul cost, stat gain per 1000 souls, spike position before and after), and the minimal fix. Do not edit data.js; write findings to council/evidence/cost/<build>.md and a summary table to council/evidence/cost/SUMMARY.md.
