# Planner-side scenario fields (range / spacing / movement / clean state) - written by the planner (abtimeline.py --range), consumed by the tester operator
Generated by `python3 -I council/tools/abtimeline.py --range <build> [--at S] [--item X] [--vs Y] --queue` into `council/sandbox/autorun/scenarios/range/rng_<build>_*.txt`. Lint: `python3 council/tools/lint_meta.py <file>` (fields below are checked when `ranges`, `layout` or `movement` is present).

| meta field | meaning | verified by the runner |
|---|---|---|
| `ranges` | comma list of intended player-to-target distances in metres, derived from game data (weapon falloff, item thresholds just inside/outside, ability ranges, contact) | readback `distance_m` per block; block invalid if it differs from the intended by more than 5% |
| `layout` | `enemies=N allies=M` plus ring spacing as fractions of the item/ability radius (`rho=0.4r,0.9r,1.3r,2.0r of R m`). Geometry = `enemies n rho`: main target at the fetch distance, the others on a ring of radius rho | readback `enemy_positions` (achieved spacing), `targets_hit` (which targets took damage / received the effect); if achieved spacing deviates >10% from intended the block is invalid for that layout |
| `movement` | `none` or a controlled target pattern (`strafe left-right period 1.5-3 s amplitude 3 m`) | moving requests carry `meta blocked_by estrafe` until the runner has an enemy-movement op; hits/fired must be reported, never expected damage |
| `required_start_state` | `stacks=0 buffs=none cooldowns=ready ammo=full hp=full target_hp=keepalive` (plus any stacks the experiment deliberately needs, with exact values) | `statecheck start_state` before EVERY block (modifiers, stacks, cooldowns/charges, ammo, hp, items, ability tiers); mismatch = block invalid, `hardreset` and repeat |
| `aba` | A-B-A order (baseline repeated after the alternative); the repeated baseline must agree with the first within the A/A noise floor | baseline drift > noise floor invalidates the pair: search lingering state, target position, tiers, missed shots |
| `order_alternation` | second repetition runs B first | recorded per block |
| `invalid_if` | explicit invalidation rules (distance off, hits != fired for stationary tests, unexpected modifier, start-state mismatch, missing item activation inside threshold) | the runner marks VALID: no with the matching rule |
| `metrics` | `per_target_damage, targets_hit, secondary_damage, kills, debuff_coverage, healing` | per-target rows; a summed total is never the headline (no double count of splash/bounce) |

Rules: every block starts with `hardreset` + `statecheck`; a setup command that returned ok is not evidence - the readbacks are. `required_start_state` clean-state control is mandatory in all range/layout/movement requests (lint-enforced). Ops used that may not exist yet in the runner: `statecheck`, readbacks `enemy_positions`/`targets_hit`/`start_state`; unsupported ones must make the task `paused-needs-design` with the reason, not run silently.
