## 2. The four crafted-case tests requested
(Harness: tools_audit_tmp/craft.py imports abtimeline, builds Violet variants, calls analyse()/cond_row(). Because abtimeline changed during the audit the exact numbers moved; behaviours listed are stable unless noted.)

 - Caveat: the 2+ rule is Kieran's statement; vdata gives `ERequirementChargedAbility`; whether a 1-charge ability counts is UNVERIFIED (F7) and printed as such. Two different point models (A strict like sp.js, A independent queues, B old) give different verdicts for the same input ("MODEL-DEPENDENT"), and no in-game check settles it.
2. Conditional thresholds (Mystic Burst single hit vs total)
 - Rule encoded: `hit` = one ability damage instance > MinimumDamage (80 / 165 / 100); `win` = spirit damage within DamageThresholdDuration (Spirit Burn 500 in 5s); `gunwin` (Recharging Rush 200 in 3.5s). Game text confirms "abilities dealing more than N damage" (citadel_mods_english.txt:87), so per-instance is the right reading; items_full MinimumDamage 80/165/100, DamageThreshold 500/5s and 200/3.5s match a7/THRESH.md.
 - Crafted: Mystic Burst as only item (800 souls, spirit 9): v1 BELOW (Living Ink 41 < 80, margin -48%, which is hand-correct for Living Ink alone) ; current version OK because Flow State MaxDamage 117 (100+1.8*9). 3. Spike rules per colour, slots, sell chain
 - Spike table: invest bonuses read from heroes.vdata (800:7, 1600:11, 2400:15, 3200:19, 4800:38, 6400:45, ...; weapon 9,12,15,18,46,54,...) equal a7/levels.json; same for every hero except tp-per-level.

1. No automated gate anywhere: merge.js writes data.js unvalidated; rebuild.sh checks syntax only; full.js is manual, has no exit code and ignores colour-change lines. "Gate: full.js clean" and "cost-efficiency FLAGs block the build" are R-level.
2. abtimeline.py (the only tool for ability-point timing, charge items, thresholds) is not wired in, has never been run on the shipped builds with fixes applied, and 24 rows in 15 builds currently flag; no known-answer test exists for it.
3. abtimeline v1 silently ignored spirit scaling on 79/145 damage props (fixed in current version, hand-verified). Any conclusion drawn from the 05:35 output (e.g. Violet Tankbuster BELOW, "no dead items" claims based on older ac_* scripts that use unscaled or model-B numbers) is suspect. The tool was rewritten four times in 11 minutes during this audit; the version used for decisions is not pinned.
4. Point-timing model is unsettled: strict single queue (sp.js, prac/ap.py), independent unlock/AP queues (abtimeline now), model B (old audit, gen/ac*), AP costs 1/2/5 INFERRED (FOUNDATIONS.md missing); different models give different verdicts for the same item; no in-game check. The 2+ charge rule (F7) likewise.
5. Sell chain incomplete: 34 of 70 core sell notes ("Sell it for ...") are not applied, sells of not-yet-owned/consumed items are silent no-ops, and 4.8k is only checked at first crossing. Slot counts and invest after those sells are wrong in every walker (walk1, sp.js, abtimeline, cost_*).
6. Rule N (swap/counter sells must keep 4.8k) is not automated; I found a real violation (violet Counters sell Opening Rounds: gun 4800 -> 3200) and 46 unresolved sell targets (solomon Grit, warden/vyper Bullet Lifesteal, mcginnis_ult Mystic Slow, etc.).
7. Rule F "every T1/T2 upgraded or named sell": 23 candidate builds/items pass walk1+check12 but fail an independent check (only ad hoc ac_rich.js tests it).
8. Cost-efficiency is largely hand-written verdicts (cost_manual.js) for one chunk; not reproducible or re-run after changes.
9. sp.js (used by CHECKLIST rule D) hardcodes 1.1 spirit/level; game data differs for Haze 0.5, Grey Talon 1.6, Kelvin/Sinclair/Viscous 1.3, Ivy 1.2 (12 builds), and counts conditional spirit as always on; it outputs SP only, the threshold comparison is left to agents.
